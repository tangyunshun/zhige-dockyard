# 第一部分：概述

## 1.1 页面定位

Workspace-Hub 是用户登录后的**第一个着陆页**，是整个系统的"空间中枢导航"。

它的核心使命是在 **3 秒内**让用户回答：**"我现在有哪些空间？我要进哪个去工作？"**

它不是具体的工作空间，不是个人中心，不是管理后台。它是"空间选择器"——展示所有桌面空间让用户选择进入。

## 1.2 目标用户

| 用户类型 | 进本页想做什么 |
|---------|--------------|
| 新注册用户（自动有个人空间） | 了解自己有什么 → 进入个人空间开始使用 |
| 个人免费用户 | 看配额够不够 → 进入个人空间干活或了解升级 |
| 个人会员 | 同上 + 考虑是否创建企业空间 |
| 企业普通成员 | 看自己有哪些企业空间 → 点进去开工 |
| 企业 Admin | 进入空间 + 快速管理成员/组件 |
| 企业 Owner | 进入空间 + 管理企业套餐/设置 |
| 平台管理员 | 本页不停留 → 从 Header 下拉进管理后台 |

## 1.3 页面核心原则

1. 信息层级清晰 → 个人空间优先，企业空间次之，概览最末
2. 操作分级明确 → 高频操作（进入）用主按钮 / 中频（升级）用链接 / 低频高风险（删除）藏菜单
3. 每种状态都有对应 → 不存在"空状态"或"出错态"无处理的情况
4. 不该有的功能不放 → 管理后台入口只在 Header，企业删除/转让在设置页
5. 模块化可扩展 → 每个区域独立组件，未来可插拔

# 第三部分：个人工作空间状态机（核心）

## 3.1 7种状态总览

| 状态 | 名称 | 触发条件 | 主按钮 |
|------|------|---------|--------|
| A | 正常使用中 | 个人空间存在，未升级/删除 | 进入工作空间 |
| B | 已升级-并行 | 并行升级，个人空间保留 | 进入工作空间 |
| C | 已升级-替换 | 替换升级，个人空间被替代 | 重新创建个人空间 |
| D | 已升级-迁移 | 迁移升级，数据并入已有企业 | 重新创建个人空间 |
| E | 已删除 | 手动删除个人空间 | 创建个人空间 |
| F | 重建 | 从C/D/E重建后 | 进入工作空间（回到A） |
| G | 仅企业成员 | 被邀加入企业，无个人空间 | 创建个人空间 |

## 3.2 状态A：正常使用中

```
┌─ zg-card ──────────────────────────────────────────┐
│ 📁 我的工作空间            PERSONAL    ● 正常 绿色  │

| 15 个可用组件                                          |
|                                                        |
|         [进入工作空间]                                 |
|                                                        |
|         升级为企业                            ⋮        |
|                                       ├── 重命名      |
|                                       ├── 重置        |
|                                       └── 删除        |
└──────────────────────────────────────────────────────┘
```

操作矩阵：

| 操作 | 位置 | 类型 |
|------|------|------|
| 进入工作空间 | 主按钮 zg-btn-primary | 主要 |
| 升级为企业 | 文字链接(带→) | 次要正向 |
| 重命名 | ⋮ 菜单 | 中性 |
| 重置个人空间 | ⋮ 菜单(红色) | 危险 |
| 删除个人空间 | ⋮ 菜单(红色) | 危险 |

状态标识：● 正常 绿色标签 (zg-tag, bg-emerald-50, text-emerald-600)

## 3.3 状态B：已升级-并行

与状态A唯一区别：
- ❌ 隐藏"升级为企业"按钮（已升级过）
- 标识改为橙色 ⬆ 并行

## 3.4 状态C：已升级-替换

```

|     [重新创建个人空间]                                  |
|                                                        |
|                                           ⋮            |
|                                     └── 查看企业空间    |
└──────────────────────────────────────────────────────┘
```

操作：仅"重新创建个人空间"（主按钮）和"查看企业空间"（⋮菜单）。

## 3.5 状态D：已升级-迁移

与状态C完全一致。唯一区别：
- 文案"已迁移" vs "已升级"
- 标签"⬆ 迁移" vs "⬆ 替换"

## 3.6 状态E：已删除

操作：仅"创建个人空间"（主按钮）和"删除记录"（⋮菜单）。

标识：灰色标签 ● 已删除

## 3.7 状态F：重建

从C/D/E点击"重新创建"后回到状态A，无需特殊 UI。

## 3.8 状态G：仅企业成员无个人空间

操作："创建个人空间"（主按钮）和"暂不需要"（链接）。

# 第十部分：架构重构与优化演进规格

为了解决单文件代码臃肿及逻辑耦合问题，系统在 v1.1 版本进行了深度拆解，形成了“轻量级控制器 + 独立业务 Hook + 模块化 Modal”的演进架构。

## 10.1 独立业务 Hook 拆分规格

核心状态与 API 请求由原 `useWorkspaceHub` 拆分为以下 5 个高内聚独立 Hook：
1. `useWorkspaceHubData.ts`：数据聚合获取与个人空间 7 种状态机状态计算。
2. `usePersonalWorkspace.ts`：处理个人工作空间创建 (`POST /api/workspace/create-personal`) 与重建。
3. `useEnterpriseWorkspace.ts`：处理企业工作空间创建表单与 API 提交 (`POST /api/workspace/create-enterprise`)。
4. `useInvitation.ts`：处理协作码输入验证、预览加入 (`POST /api/workspace/join`)，以及空间分享生成邀请码的逻辑。
5. `useDeleteWorkspace.ts`：管理重置个人空间、注销企业空间的前置校验 (`GET /api/workspace/check-delete`)、密码二次身份验证 `StepUp` 阻断分发。

## 10.2 独立 Modal 模态框规格

所有交互弹窗完全独立并封装在 `components/workspace-hub/modals/` 路径下：
1. `CreateEnterpriseModal.tsx`：企业空间创建。
2. `UpgradeModal.tsx`：个人空间升级，提供并行模式、替换模式、迁移模式卡片选择，提交后端并回写 `localStorage` 缓存标志。
3. `JoinEnterpriseModal.tsx`：验证并加入协同空间。
4. `ShareWorkspaceModal.tsx`：生成邀请码及分享选项。
5. `DeleteConfirmModal.tsx`：通用删除确认组件，接收校验词 (`confirmWord`)、警告列表、目标空间信息及加载态，完成物理删除和重置的安全防护。

## 10.3 体验加载规格

页面加载期间 (`isLoading === true`) 统一展示 `PageSkeleton.tsx` 闪烁骨架屏组件，对齐 Bento 栅格结构，优化交互感知。

## 10.4 控制台 IDE 内部布局与权限防闪烁深度优化规格

系统在 v1.2 版本针对控制台 IDE 内部布局 (`WorkspaceInternalLayout.tsx`) 和设置页 (`settings/page.tsx`) 进行了深度规格重构：

1. **权限初始化与防闪烁**：
   * 初始状态 `authData` 声明为 `null`，不再使用任何硬编码的假数据权限。
   * 在进入或切换不同工作空间（`loadWorkspace`）的第一行，必须执行 `setAuthData(null)` 重置权限，杜绝前一个空间权限残留造成的 UI 闪烁。在加载中及 `authData` 未就绪期间，强行展示优雅的 Loading 缓冲圈。
   * 默认基础组件 ID （"C01", "C02", "C07"）统一抽取并常量化为 `DEFAULT_ALLOWED_COMPONENT_IDS` 并导入使用。

2. **个人空间商业化受限规格**：
   * 对个人空间用户，通过 `GET /api/user/profile` 接口动态提取当前用户的 `membershipLevel`（会员等级）。

## 10.8 空间重置所有者鉴权、算力额度自动初始化与沙箱文件上传优化规格 (v1.6 版本)

为了彻底修复数据重置失效、算力初始化死锁导致的按钮置灰等核心 Bug，并向用户提供高可用、逼真且精美的“标书/文档上传”调试体验，系统在 v1.6 版本中实现并规范了以下技术方案：

1. **一键重置空间数据全栈所有权解封规格**：
   * **鉴权策略升级**：由于个人自主空间（`PERSONAL`）在创建时并不会在协作成员表（`workspacemember`）中插入关联记录，导致原本依赖查询成员表判断管理员权限的清空数据接口（`POST /api/workspace/clear-data`）出现 403 鉴权失败的严重 Bug。
   * **数据库多链路授权**：重构后端 clear-data 控制器。优先读取 `workspace.ownerId` 属性，只要满足 `workspace.ownerId === userId` 的直属所有者判断，或者满足成员表内 `role IN ('OWNER', 'ADMIN')` 的协作管理员判定，即可直接通过权限拦截。同时根据个人空间类型专门过滤仅清除个人岗位关联数据而保留空间实体，为用户的数据资产 and 算力清空提供百分之百的稳定返回。

2. **算力配额获取与新空间自动初始化兜底规格**：
   * **配额获取初始化防死锁**：全新创建的工作空间默认在 `workspacequota` 算力配额关系表中没有条目，这导致原配额获取接口（`GET /api/user/workspace-hub/quota`）在遍历时返回空对象，前端从而将其置为 `0 Tokens`，进而因为防欠费策略把“运行组件服务”按钮强行变灰。
   * **配额事务性注入**：在获取配额的遍历流水线中，如果发现空间对应的 `workspacequota` 为空，自动在后台根据当前用户的会员等级（`membershipLevel`）直接向数据库新建配额并注入对应算力（免费等级：10,000 Tokens，金牌会员：50,000 Tokens，钻石会员：100,000 Tokens），消除新空间算力配额置灰的卡死痛点。

3. **高颜值本地文档上传物理沙箱与去模拟化规格**：
   * **UI/UX 虚线文件拖拽上传区**：在控制台输入参数框的正上方，新增一个样式完美的虚线文件上传拖拽区（`.zg-upload-pro`，锁死 `8px` 圆角，使用主色调 HSL 浅蓝背景）。上传卡片的高度由原来的 `h-20` 大幅拓宽至 `h-32`，带有了更详细和更真实的“沙箱传输物理销毁”解释说明，以确保用户数据资产的合规可信度。
   * **完全去模拟化专业文案**：去除了所有可能降低专业体感的“模拟运行”、“Mock”字样，将按钮与核心功能统一提升规范为“**运行组件服务**”（运行中显示“服务运行中...”）、标头修改为“**组件输入参数与数据源**”、控制台标题修整为“**运行结果与审计日志**”，提升工业级专业体验。
   * **重置清空逻辑重塑**：重构了“重置清空”按钮的行为。重置清空按钮不再是重新加载 demo，而是一键重置并清空输入数据及终端日志。Demo 数据重新加载全量交由“加载预设 Demo”按钮完成，避免功能职责混淆。
   * **元数据结构化转化与安全校验**：当用户点击或拖拽本地文件到上传区时，前端动态获取文件名、大小、类型等真值属性，并自动生成一组 SHA-256 校验码及安全沙箱隔离配置指令，将其装配成真实规范的 JSON 数据报文回填至组件输入参数中，让用户体验真正的安全审计。

4. **算力额度欠费橙色警示卡片规格**：
   * 在 textarea 的下方，当发生 `workspaceToken < cost` 且非特许受限角色时，在运行栏与输入框之间条件渲染高度醒目的橙色高颜值警示卡片（对齐 HSL 主色，圆角 `8px`）。不仅从代码上将运行按钮安全置灰，而且向用户清晰告知当前空间的余额状况以及平台推理集群的算力消耗机制，解释变灰原因，避免突兀的不明卡顿。

5. **全局字号大厂级标准化收拢规格**：
   * 依据现代移动及桌面端的高端视觉审美，系统将全局字号阶梯标准化为以下双主干层级：
     * **标题与 Label 等核心板块（14px 黄金大字）**：统一使用 `text-sm font-bold text-slate-800`，如表单输入项 Label、组件各详情卡片标题、控制台面板核心标头等。
     * **提示与辅助信息（12px 黄金小字）**：统一使用 `text-xs` (如 `text-xs text-slate-500`、`text-xs text-red-500` 等)，如字数统计显示、错误红字、帮助备注说明、FAQ 的问与答内容，彻底从底层排除了混乱难读的 `text-[9px]`、`text-[10px]` 和 `text-[11px]`。
