## 5. 到期写边界保护与正常业务

- 事务外候选扫描仅用于筛选，不作为最终降级授权。实际写入时必须确认当前套餐仍是本次候选对应的有效到期事实、没有续费/换套餐，并维持同一空间与对应quota关系。
- 优先沿既有Prisma事务与条件updateMany/count模式做最小改动；匹配不到应跳过，不能随后更新quota或计入成功。不要用先read再无条件update替代写边界保护。
- 扫描后续费、换套餐、期限变化或quota绑定变化时不覆盖新事实；失败/并发败者不清新期限、不清新席位，不写错误quota。
- 同一空间的套餐/周期/额外席位和对应quota席位修改同事务完成；任一步/提交失败都回滚，不出现一边降级一边未改成功。禁止根客户端写逃逸。
- 重复请求/两次扫描同一候选不会重复制造变更或错误成功记录。响应downgraded/affected只统计实际成功；跳过/失败结果诚实，不把候选数当成功数。
- 标准套餐席位继续来自现有配置，不借本批改价格或套餐配置。不新增补偿性赠送；配置无法安全支持处理时诚实拒绝，不写库修配置。
- 明确到期临界时刻语义并固定测试；未到期和无期限记录保持原状，不能把无期限猜成到期。既有请求侧席位过期拒绝与续费/支付保护不退化。
