## 3. 准入规则：可信成本与实际单次预算

- 适用分支先按服务端最终解析的模型部署/价格来源和实际计费模式判断。客户端不能通过传provider/key/baseUrl、伪装BYOK或结算模式绕过。
- 保留现有收费配置，不自动涨价或多扣。预算使用本次实际会扣的合法整数点数及统一point-rate单位；不能比较未真正扣到的小数原值或无关目录标价。若当前配置会被consumePoints取整而产生歧义，诚实拒绝该损坏配置，不改库猜价格。
- 成本使用最终部署的可信生效供应商成本，区分缺失与明确免费：非免费缺失一侧且该侧可能产生用量、状态不可采信、币种/规则无法可靠解释、数值非法或读取失败，都不能按0/默认厂商价继续。
- 明确免费只有现有权威数据足以证明时才接受，不把null、未配置或OBSERVED_ONLY当免费。不要新增“默认允许”的后门。
- 供应商成本与本次名义预算在同一微元/币种下用安全整数/BigInt计算，单位与舍入有独立复算；复用统一point-rate，不以浮点近似账务。
- 最低止损：保守执行成本上界大于本次名义预算则拒绝（不能保留两倍容忍区），成本等于/低于预算且其余既有门禁通过才可继续。本规则不批准最低利润率，也不把名义预算当现金收入；已有额外限制不得被放宽。
- 不能建立可信预算或成本上界时拒绝该请求，不用新增默认价、临时markup或虚构补贴来造出可运行结果。

可新增最小严格准入计算函数，但不要全局改写旧展示/管理端成本估算helper以牵连无关保存/初始化流程。旧告警可保留作诊断，不能代替硬门禁。

## 4. 预算必须对应实际将执行的请求

- 在发生实际执行之前统一生成最终systemPrompt（包含真实会展开的占位符）与userPrompt、实际maxOutputTokens；同一份请求参数用于准入和adapter.execute，不在检查后另算一个更大的输出上限。
- 按当前真实执行路径计算，不假装已经实现所有合同steps。若路径包含多个调用/重试或不可确定开销，预算须覆盖实际可能发生的全部费用，不能只看第一段就宣称覆盖；无法界定就拒绝该路径。不要借此实现新多步编排。
- 输出预算必须覆盖真正传给适配器的硬上限，包括目录×3/env/default分支；不能把缺失合同输出当0，也不能悄悄缩短用户应得结果来通过价格检查。
- 输入成本需覆盖最终实际提示词/材料及已知调用开销。现有字符估算是估算，不是严格上界证明；只有可核查的保守边界才可称覆盖。无法可靠限定时诚实暂停受影响请求，不偷偷换模型或忽略未知部分。
- 价格/预算快照只保留必要版本、来源、单位、计费模式与准入结果，不记录密钥、原始材料/提示词或全量模型响应，不新建表/审计平台。可复用既有任务配置/内部日志，不把内部成本字段公开到游客接口。
