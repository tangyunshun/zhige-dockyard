## 三、S01：统一字节与配额语义

- workspacequota.storageUsed / storageLimit 的单位为字节，判定和增减使用 BigInt。不得把套餐 MB 直接写成字节，不改变既有套餐/授权数值。
- 缺少配额记录、非法配额、未知占用不得默认为无限。新增物理文件应在存储副作用前明确拒绝；缺配置返回稳定的未就绪错误，0 表示不能新增正字节文件，明确的服务端既有 -1 才表示不限。不得接受客户端设置无限，不新增无限授权。
- 非法负值（小于 -1）、负用量、输入非整数/非有限值或不可安全转换的 number 应拒绝。0 字节不扩大占用，但仍经过身份、空间和配置检查；保留现有文件类型/单文件大小规则。
- 判断真实已接收 buffer 的字节数，不相信客户端 fileSize。JSON 文本兼容上传没有物理文件时，不得按客户端伪造 fileSize 增加物理存储用量；保留合法文本资料创建能力，不按文本字符数假装物理文件大小。
- 错误给稳定 code 和可读 error；配额不足提示当前占用/上限和整理或联系管理员的办法，不虚构购买入口或诱导用户为配置错误付费。

## 四、S02：原子占用，不能先查后加

- 用数据库级条件更新或锁定事务，使“检查当前上限 + 预留这次字节”成为同一个受保护动作；不能依赖进程内锁、内存 Map 或先 findUnique 后无条件 increment。
- 限额 100、占用 0、两笔各 60 的并发请求，至多一笔进入物理存储；另一笔明确拒绝，最终占用不得 120。限额/用量并发变化同样必须在写边界核验，不能用过期快照放行。
- 明确预留、已确认、待清理占用的口径，同一字节不能在预留和确认时重复增加。已有 -1 空间同样记录真实占用，不能只跳过记账。
- 操作需要可持久追踪的唯一身份，足以关联 workspace、操作者、文档/对象、字节和状态，防重复确认/释放。复用现有 document 状态和元信息等可行模式；若必须增加字段或最小操作记录，只服务本闭环，交付离线 schema/迁移草案和回滚影响说明，不新建通用作业平台。
- 不在数据库事务中调用模型/OCR/解析；不要用长期持有数据库锁覆盖慢外部工作。若所需结构未就绪，诚实拒绝存储写入，禁止在业务请求中自动 DDL。

## 五、S03：两条上传链路一起闭合

- upload_doc 的空间归属/权限、必填信息和配额检查必须在写文件前完成；禁止在 401/403/缺参数后留下文件或预留。附件必须核对父知识条目 workspaceId 与请求记账空间一致，并保留创建人/管理员权限。
- 两条物理上传都使用相同的配额占用协议与文件存储路径规则，不能普通上传修了而附件继续直接 fs.writeFile + addStorageUsed。
- 保存成功必须有可关联的物理对象、文档元数据和已确认占用；新建中的内部状态不能被列表/下载误当成功资料，不能混用业务审核 PENDING 与存储未完成状态。
- 覆盖文件保存失败、后续解析抛错、document 创建/提交失败、记账失败、确认失败、客户端重试。已确认不存在文件的失败释放预留；文件删除失败或外部操作结果未知时，保留可追踪占用和恢复信息，不能先释放额度再遗留真实文件。
- 进程重启/中途退出不能让未跟踪文件无限积累。对象位置与操作身份须可恢复地关联；对超时在途状态先核实对象和操作事实，不按过期时间盲目释放仍在写入的预留。提供本批最小的恢复/重试方式和重复执行保护，不扩展成通用恢复系统。
- 不更改解析器本身、OCR 预算或 F14 并发限流；存储预留期间解析失败的清理属于本批。

## 六、S04：文件键与物理位置必须一致

当前 file-store 本地保存会把 assets 前缀拼两次，而读/删会剥掉前缀；附件另有直接写盘路径。请修复这条契约，验证保存返回的 filePath 能被现有鉴权读取和删除定位到同一个对象。

保留本地和已存在的 S3 驱动接口，不主动切换驱动、读取密钥或访问真实桶。对历史路径兼容仅处理代码中已确认的表示方式，路径必须限制在该存储根/空间内；不得自动迁移、移动或删除历史文件。需要迁移的未知存量另行报告，不把未知对象当成不存在。

deleteAssetFile 不得把权限错误、磁盘错误、云服务错误都当作“已经不存在”。只有确认为不存在才可按幂等成功处理；其他失败须返回或抛出可供上层保存失败状态的结果。不要只修配额函数却继续让物理删除假成功。

## 七、S05：删除、重复请求及旁路

- 公开资料软移除、知识软删除和可恢复记录仍保留文件，不释放其物理占用；恢复也不重复增加。纯文本/无物理文件不因客户端历史 fileSize 释放别人的容量；有路径但大小未知的历史记录应报差异，不假定为 0 后宣称对账通过。
- 彻底删除只有在确认对象已不存在后释放一次；使用原子扣减与文档/操作状态条件，不能读 used 后绝对回写。用量 100 同时删 30 和 40 应为 30；同一对象的并发/重试只能扣一次。不能用 Math.max(0, ...) 掩盖重复扣减或历史差异。
- 物理删除失败不先删除唯一可追踪记录再释放空间；记账/数据库失败后保留可重试依据，不吞异常后返回完整成功。返回失败、处理中或部分成功必须与真实状态相符。
- batch_delete_assets 必须经过同样的空间、归属、私密资料和既有治理权限，不能直接 deleteMany 绕过文件与占用。保留既有普通成员公开资料删除申请规则，不借本批重做 RBAC。
- clear-data 只调整文件清理/存储计量部分：与同空间上传竞争时不能无条件 storageUsed=0。可对成功删除的唯一对象条件扣减，或用明确的空间级协调阻止竞争；失败对象仍需计量和可追踪。不要顺手改任务/组件重置、默认装配或审计清空的其他策略。
- 批量部分失败按实际成功项更新 UI 和数量，不能让前端删掉全部选中项后宣称全部成功。

## 八、S06：用户可见结果与只读对账

现有资料上传入口位于 WorkspaceInternalLayoutV3；知识附件入口位于 app/knowledge/page.tsx。只改动本闭环所需错误/处理中/刷新逻辑：失败保留用户输入和可重试状态，成功刷新真实资料/占用；不得把失败乐观显示成功。

提供最小只读对账逻辑/报告，比较额度快照、按唯一对象统计的文档、预留/待清理与实际物理对象，区分差异、重复引用、缺文件和孤儿对象，软删除仍纳入占用。对账本身不能修库、删文件、自动清零或释放未知预留。先用内存/临时夹具验收，不查询真实库/磁盘/云桶；定期只读核对的运行方式写入说明，不创建新的调度平台或主动设置定时任务。

未知历史物理对象、驱动来源和大小必须标为待核实，不用默认 0 掩盖。此批不重做所有个人/管理员统计页，只保证直接影响本次上传/删除的结果诚实。

## 九、S07：必须提供的运行验证

正式新增定向测试应调用实际 handler/service 和实际配额函数，仅把 DB、文件 IO、解析器等外部边界替换成受控夹具。不能把整套存储服务 mock 成成功后声称闭环通过。

| 场景 | 必须观察的结果 |
| --- | --- |
| 配额缺失、0、非法负数/负用量 | 存储副作用前拒绝，无文件、无成功资料/错误占用；明确错误 |
| 明确已有 -1、正常额度、恰好边界、BigInt 边界 | 允许/拒绝正确，字节计量准确，无 number 精度绕过 |
| 同空间两笔竞争、不同空间互不影响 | 超限一笔拒绝；跨空间不共用锁/余额/占用身份 |
| 两条真实物理上传入口 | 均经过原子占用，保存对象可读，元数据/占用一致 |
| JSON 文本伪造 fileSize | 不占用或释放不存在的物理文件容量 |
| 401/403、父条目跨空间、缺必填参数 | 无落存储/无预留/无成功记录，权限未放宽 |
| 保存失败、解析失败、建记录/提交/确认失败 | 无假成功；安全清理或保留可恢复占用与对象关系 |
| 进程重启/断点恢复、操作重放 | 无重复占用/释放，未知结果不盲目释放 |
| 并发删除不同文件、同文件重复删除 | 总量正确、只释放一次；其他文件占用不受影响 |
| 物理删除失败、配额写失败 | 不假报已释放，保留恢复线索；批量如实报告部分结果 |
| 软删除/移除与恢复 | 文件仍在则继续占用，恢复不重复计量 |
| 批量硬删除、clear-data 与上传竞争 | 不绕过协议，不错清零，不删其他空间对象 |
| 本地路径、历史路径、S3 夹具 | save/read/delete 对同一对象一致，无真实网络/桶访问 |
| 只读对账 | 正常与差异均可解释；DB/对象写方法全部 0 |

并发夹具需要可控交错/屏障和真实条件求值，不能串行调用假装并发；必须检查文件、文档、计量、状态和响应，不只看返回码。内存测试不证明 MySQL 隔离/锁，报告真实数据库并发验证未执行，不能写成生产验证通过。

运行本批明确的安全测试文件，再运行上一批 12 个明确 R0 回归文件（见 R0-I2-independent-review/validation-results.json 的 fileList，基线 407 项）及 tsc --noEmit --incremental false -p tsconfig.json。禁止 npm test 或未过滤 Vitest；仓库有真实数据库集成测试。不要在本批配置中加入旧审核的缺陷复现文件冒充正向验收。

前端若改动，提供实际入口、操作和成功/拒绝/失败表现证据；可使用隔离 API 的本地浏览器验证，不能触发真实支付、模型或数据清理。无法浏览器验证时明示限制及实际 JSX/回调替代证据。
