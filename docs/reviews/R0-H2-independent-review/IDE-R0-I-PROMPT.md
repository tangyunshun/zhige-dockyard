上述是检查范围，不要求每个文件都修改。先追踪实际消费者，避免页面提示暂停而 POST 仍可收费。

### 服务端

1. 身份、空间权限、合同/输入等原有门禁保持；在服务端解析的模型计划被识别为 USER_BYOK 后，返回稳定 409、success:false、code:BYOK_BILLING_POLICY_UNCONFIRMED，并附用户可理解的暂停说明。默认/auto 和手动指定均不得绕过。不以客户端填入的来源、费率或模型标记决定放行。
2. 正常已识别的 BYOK 应在任何配额重置写入、扣点、hold、任务创建或 execute 前拒绝；不再因价格缺失/异常而回退固定点数继续收费。初次模型/报价裁决异常不能仅日志吞掉后继续到 BYOK 执行。
3. handler 存在前后两次解析模型的流程，核对最终计划，防止早期平台计划、最终 BYOK 的交错绕过。最终 BYOK 仍必须在扣点/hold/任务/execute 前拒绝；两次计划交错夹具中也不能产生任务或资金副作用。不要改成请求客户端确认即恢复或静默替用户换平台模型。
4. 暂停由服务端强制；前端按钮状态不作为安全边界。生产结算开关、ALL/WHITELIST 不得成为放行 BYOK 的后门，既有平台结算分支和成本门禁保持。
5. 报价接口对同一 BYOK 任务给出相同的暂停事实：明确 blocked/canExecute=false、稳定码、points/yuan 为 null；若原 API 使用成功数据封套也可保留结构，但不能让客户端将其解释为可扣点报价。保留身份与空间归属校验，GET 仍只读。不调用真实模型，不触发惰性 DDL 或更新配置。
6. 旧算法如为保留历史复算留在纯函数内，不代表当前可收费；不要改算法费率、默认数值或历史账单来“消除问题”。本批只封住当前任务收费路径。不要自动退款或重算历史交易。

### 用户与管理员可见结果

1. Studio 中明确说明“自带模型的任务调用暂不可用，平台收费口径待确认，本次未扣点、未调用模型”。拒绝后恢复忙碌状态，不伪造任务成功，不弹充值引导来解决暂停。
2. BYOK 关联预估不能继续显示正常应扣价或承诺“按实际 Token 只收服务费”。报价请求失败也不能回退显示固定点数为可执行 BYOK 报价。
3. 模型配置、绑定、默认设置与历史保留；“已绑定/已设默认”不等于当前任务可执行。必要说明同页可见，不以成功绿色状态掩盖暂停。
4. 管理员现存费率数值仍可作为已存配置展示，不能宣称当前 Studio BYOK 任务收费即时生效或已商业上线。不要删除配置或扩大管理员权限。
5. BYO 连接测试与其他模型调用入口不属于本批恢复/重做范围；如仍能单独发起连接测试，必须如实写明该入口可能调用供应商，不能报告“所有 BYOK 外部调用均被暂停”。本轮测试禁止真实调用这些入口。
