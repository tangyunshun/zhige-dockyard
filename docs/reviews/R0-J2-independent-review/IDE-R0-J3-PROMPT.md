## 一、J-RELEASE：物理未清理，实际占用不能先释放（最高优先级）

当前代码虽然将文档删除与扣量放在事务中，却在物理删除前已经把额度放回；失败后补一条 PENDING_CLEANUP 记录不参与新增上传准入。独立复现：限额 30 → 删除失败后 used=0 → 再上传 30 成功 → 物理共 60。此项违反原 F13，不是可接受的新“DB先行”收费/资源口径。

必须达到：

1. 对象未确认不存在前，仍计入可执行准入的占用/预留；待清理文件不能给下一笔上传腾出容量。不能仅加提示、事后尝试补记账或查询一个尚未持久写入的待清理记录来遮盖提交窗口。
2. 在破坏性提交或外部删除之前，持久认领唯一删除操作和对象定位；实际字节、主体、空间、状态能关联。物理 IO 在数据库短事务之外；确认已删/不存在后，再以受保护状态转换只释放一次。优先利用现有 storageoperation，不再新增一套未接线服务或通用队列。
3. 记录逻辑删除可以先发生，但恢复线索和被占用的容量必须同时可靠保留。待清理记录写失败不能仅打日志后删除最后一份元数据并释放容量。重启后能找到正在清理的对象，而不是依赖日志猜测。
4. 同对象并发、重复请求、删除与清空交错、提交失败/重试，都只释放一次。继续保留普通重复释放、漂移不清零的已通过改进。
5. 共享引用用相同的真实对象身份判断。`assets/w1/shared` 和 `w1/shared` 是现有已知别名；不能按原始 filePath 字符串相等查询后遗漏仍保留的引用。存在保留引用时，不删除对象、不释放仍用的容量。历史未知/大小冲突先保留并报告，不开发新的去重产品功能。
6. 删除 API 如实返回逻辑完成、物理清理待处理、失败等状态。batch_delete_assets 的 cleanupPendingIds 必须接到现有提示；batch_remove_assets 也需返回相应未完成结果，不能直接计数为完整成功。两处回调保持正确筛选/HTTP处理，只补待清理说明和实际可用容量状态，不重做页面。

## 二、J-UPLOAD：完成可定位、可恢复、可终结的失败协议

1. 两条上传的 `saveAttempted` 必须在开始保存之前标记；现在成功 await 后才置 true，未知保存分支不可达。仅移动布尔值还不够：目标对象键须在外部写入前分配并持久关联操作，不能由保存函数私自生成一个丢失响应后无法关联的随机路径。
2. 写入已经产生对象后抛错/超时，保留占用，进入持久待核实状态，API 返回稳定 code/opId。恢复按该操作可定位对象并核实事实，不按时间/缺返回值盲释；不扫描或移动真实历史文件猜测归属。
3. 清理已经完成且额度已释放时，操作进入对应终态，不继续 RESERVED/“活动状态”；操作状态与净占用保持一致。同操作重放返回原事实/明确状态，不重新写新对象，不重复释放。
4. 确认失败后，文档清理也失败时，不能 `.catch(()=>{})` 然后删除文件、释放占用，留下 APPROVED 文档。保留可恢复的资料/操作状态，错误诚实；确认、文档、物理对象与占用失败都能定位并重试。
5. delegate 未生成或表/列未就绪，在任何副作用前稳定拒绝 503/明确 code；不是 undefined.findUnique→500。补实际模型能力检查和部署前置条件，不在业务请求中生成客户端或建表。
6. P2002 并发分支与普通重放必须使用一致的空间/操作者/字节/类型/状态核验。现在并发分支缺 userId/状态检查，不能对另一主体的操作返回 deduped。复用现有小范围校验即可，不新增通用鉴权抽象。
7. 保留两条上传的正常确认、0 字节、JSON 文本不伪造字节、单次授权后解析、父条目空间校验与原子预留，不修改 F14 解析实现。

## 三、J-CLEAR：删行认领、扣量与恢复状态不能断开

本批 clear-data 已实际改动，保留“失败文件留记录”和“扫描后新上传留完整记录”两个通过项。剩余缺口：删除文件→条件删文档成功→独立扣量抛错时，文件和文档都无、额度还在、没有本次恢复操作。只避免全空间 deleteMany 不足以完成故障恢复。

- 与上一节可靠删除协议一致：对象认领/状态先可持久追踪，最后的元数据终态与额度释放受同一原子条件控制；提交失败留可重放依据，不能永久丢掉这条扫描对象。
- 不因为异常、漂移或并发就假报完全成功。无需自动修历史漂移，只保存可诊断事实与安全状态。
- clear-data 只有共享保留、没有文件错误时，也不能返回“纯净出厂状态”；反馈实际清除/失败/保留/待处理数量。共享引用在同一扫描集合的处置按现有安全规则处理，无法安全完成时保留并明确提示。
- 保留原空间授权、确认文本和非存储的任务/组件/默认初始化/审计政策，只改文件计量协议及必要结果说明。
