## 五、修复 C4：三个调用者统一确认“真的开通”

独立反例：两个 UpgradeModal 收到 success:true、orderNo存在、但没有 payUrl/free，仍显示升级成功并调用完成回调，中枢还写已升级标记。当前网关正常实现应带 payUrl；这是异常响应的防御缺口，不要夸大成已发生真实付款漏洞。

统一以下行为：

1. 后端成功且有明确待支付结果/payUrl：进入收银台或待支付状态，不写已开通标记、不触发完成回调，不显示开通成功。
2. 后端明确真实免费开通完成（按本API契约核对success、free、返回空间等）：才提示成功、写相应标记、刷新/回调/关闭。
3. HTTP200但没有完成证据、缺收银台信息、success:false、协议不一致：保留输入，提示待处理或错误；不当作已开通。不擅自重试导致重复下单。
4. HTTP错误/网络错误：显示message优先的说明，保留选择；不得制造成功状态。

对三个实际调用者都提供行为证据：独立页、studio弹窗、中枢弹窗。不要为了统一状态引入全站通用流程框架或无关UI改造。
