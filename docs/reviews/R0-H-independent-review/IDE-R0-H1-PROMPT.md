## 2. H-BOUND：上界须有依据，未知费用不能消失

当前estimateCombinedTokenCount只是CJK每字1、其他字符约4个1 Token的粗估。把它传给命名为conservativeCost的函数，不会自动成为上界。报告承认估算不是证明，不能替代原本要求的拒绝行为。

- 为当前执行建立可核查的输入Token/费用边界来源，并与实际部署、最终提示词/材料和输出上限对应。可沿可信服务端模型硬限制、可信适用分词/请求约束等已有事实做最小实现；不能随意加字符倍数后称为可靠保证。
- 估算可留作展示/诊断，但不能仅凭数值是非负整数就认定成本可靠。缺少可信边界、边界不适用于当前协议/请求或无法覆盖真实调用开销时，返回稳定“无法核价/未就绪”错误，零扣点/hold/execute、无RUNNING/SUCCESS。
- 仍保留至少一个具有明确可靠边界的正常PLATFORM请求和合法明确免费对照，不能永远拒绝所有任务来通过。明确免费仍受原输入/能力/权限限制，不借此开放无限资源。
- 最终pricing.rules/可能费用项必须有明确处理：未知且可能影响费用的规则不能因接口类型没声明它就被静默忽略。无法可靠解释时拒绝；不要求实现通用规则引擎，不把任意规则自动加到账单，更不能涨价。
- 支持的费用类别应明确；若既有缓存/其他类别可能增加费用且无法给出保守覆盖，也应拒绝相应路径。若某规则有既有依据证明不影响本次费用，可明确说明并固定测试；不能仅以“不认识”断言无成本。
- 继续使用同一份最终systemPrompt/userPrompt/实际maxOutputTokens；不缩短输出、不换模型、不增加重试来造出可运行结果。
- 快照/内部诊断区分“估算值”与“用于准入的可靠上界及来源”，不保存原始材料、提示词、密钥或模型完整响应，不新增表/预算平台。

预算仍是现有实际整数扣点的名义预算，按原统一单位BigInt比较，不改变任何售价/充值比例/markup配置。名义预算不是现金收入，更不构成新利润或补贴授权。
