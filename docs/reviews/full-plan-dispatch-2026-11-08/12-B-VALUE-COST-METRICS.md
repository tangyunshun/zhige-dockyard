# 第12批给B：R5用户价值、留存与成本经营视图

开始：9和10交付，可与A11并行。依据原§6.2、§10/R5。目标是让负责人看清真实使用价值和支出风险，不以漂亮数字替代利润证据。

## 范围与数据口径

先盘点现有task/attempt、订单/渠道事实、账本/用量/成本、企业/组件/模型维度与原有usage/finance页面，复用现有只读API。可补必要最小事件和聚合视图，不引入外部分析平台或任意敏感埋点。

## 实现

1. 明确事件/指标字典：场景到开始、首次有效成果及耗时/阻断、质量失败/退款、后续重复完成/复用、真实付费/续费、可归因成本和恢复差异。结构验证通过与用户认可分开，下载一次不能当满意。
2. 去掉同日刷新、同任务重试/attempt、模拟、内部测试、赠送和人工补录伪收入。样本/观察窗口/时区/归因依据明确；低频工作不强求DAU，不编留存或LTV目标。
3. 收款、已消费服务口径、点数、供应商成本、免费/推广、固定支出分栏。未知成本/收入归属标未知，成本覆盖不全不能显示完整利润。已购未消费余额不简单视为赚到的钱，财务口径仍由负责人决定。
4. 成本卡覆盖多步/失败/重试/文件/OCR/存储下载/支付与直接支持等已有可获得事实，缺项显式列出，不填0；目标贡献率/风险准备未定时仅做参数化离线测算，不写回售价或预算。
5. 数据归属和查看/导出权限严格，用户不看其他企业明细，管理员只读无资金写；聚合接口不重算/补扣/补权益。必要事件只含最小业务ID/版本/原因，不收正文、验证码、密钥或敏感材料。
6. 有差异/unknown成本/质量下降时给明确观察提示，不自动扩大投放、赠送或切价格。活动配置只是复用现有批准规则，不开发新奖励系统。

## 验证和交接

用可重算小样本独立算每个指标：重复/跨天/时区边界、不同租户、同任务多attempt、模拟/赠送排除、部分成本缺失、退款/未履约时差、权限和导出；查询零业务写。UI显示空/未知/失败/样本不足而不是虚构0或收益。

交P12数据字典/公式与来源、样本重算证据、API/页面清单、隐私与成本缺口、原决策待定项、模型片段和handoff。不用真实客户数据/财务账单，不对外发布增长/盈利结论。
