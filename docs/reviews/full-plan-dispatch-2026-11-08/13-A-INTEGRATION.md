# 第13批给A：唯一共享集成与最终版本定格

开始：5–12全部handoff实际到位并停止写入；第4批的中间模型/配置基线也已交。你是本阶段唯一schema、migration、共享配置/导航/类型补丁集成人。依据原§9/§13，不新增业务功能。

## 集成动作

1. 核对各批起止SHA、实际文件、测试和全部未完成/决策门。旧版本测试不套在新源码上；已交付后又修改必须重交。发现越界/缺口退原编号，不自动新建第15批。
2. 以第4批最终schema为起点，逐个增量并入5–12已证明必要的模型片段，保留已有parse/OTP/资金事实和所有历史字段。核对delegate、外键/唯一键、索引、状态与事务客户端，不覆盖整份文件、不把所有逻辑记录都建新表。
3. 统一仅被各批提出的最小共享依赖/配置/导航/页面/类型适配；保留旧接口必要兼容与原业务断言。不改变既有价格、赠送、生产模式/结算硬关闭、F07暂停或角色真实授权。
4. 交一套一致的离线迁移/兼容/回滚说明；保留已部署状态未知，不真实apply。离线validate/generate需要隔离真实.env/网络/库，无法隔离就列门，不能业务请求建表/生成客户端。
5. 检查全链路契约：报价→预算/资金→task/attempt→供应商事实→成果→费用/恢复→指标；支付→可信收款→一次履约→查询。接口错位只做最小集成修，业务不变量缺陷退所属实现者。

6. 原§4.2/CF-F10的请求路径DDL逐项核：业务API/查询不得自动ALTER/CREATE或生成客户端；已有缺口转为离线迁移和未就绪拒绝。配额双向关系只按第7批已核实映射准备离线方案，不猜历史关系自动修库。

## 检查和交棒

跑精确集成用例及受影响原回归、严格tsc；任何人为放松断言/类型/模式门禁视为未完成。确认各阶段决策阻断仍是阻断，缺表/能力/预算未就绪仍在外部费用前拒绝。

输出P13 final-candidate-manifest.json、集成diff、schema/migrations与未执行声明、契约对照、tests、已知失败/决策/环境门、handoff。定格后所有业务源码停止改动，第14批接手同一版本。

不真实库迁移、付款、模型、部署或回填历史账。不把“代码能构建”写成生产可用。若业务返工造成源码变更，按原编号收新handoff和SHA后重新定格，仅补受影响验证。
