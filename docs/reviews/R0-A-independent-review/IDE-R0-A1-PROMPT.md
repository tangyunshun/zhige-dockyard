## 2. 修复A1：免费资格不等于价格0

重点：src/lib/workspace-plan-service.ts 的 verifyEnterprisePlanForCreation，及两个企业创建入口。

当前monthly===0 && yearly===0就返回FREE，导致零价PRO/ENTERPRISE等非基础档被直接创建，独立复现两条入口均200并写高级配额。

要求：
- 复用现有DEFAULT_WORKSPACE_PLAN与已定义免费基础策略，不新建免费高阶套餐政策。
- 严格读取真实目标记录、启用/在线状态、目标key及价格；不回退常量授予企业权益。
- 只有“既有免费基础身份”且真实月年价格均为合法0才可进入免费创建；其他零价目标也必须拒绝或要求明确授权，本批不新增该授权流程。
- 价格使用安全、非负整数校验，拒绝null/undefined/NaN/负数/小数等；负价不是合法PAID。
- 免费基础档若变为正价，不得按旧常量免费开通。
- 两个企业创建入口一致执行；拒绝前无空间/成员/配额/装配/赠送/成功订单写入或外部调用。
- 不依据客户端paid、amount、orderNo、role、paymentMode或模拟参数放行，也不把付费会员身份当作已购买目标套餐。

## 3. 修复A2：企业门禁限定企业，不改变个人初始化

把企业付费资格门禁限定到ENTERPRISE。个人分支恢复本批之前的个人初始化规则与已有配置读取语义，不新增个人购买企业套餐的要求；不要简单删除整个函数检查导致企业保护回退。

验证个人请求不受企业purchasable、停用、价格及记录缺失的新增门禁影响；比较的是本批引入的差异，不要求你扩大修改其他既有个人业务规则。个人请求带plan=PRO也不能据此获得高阶企业权益。

## 4. 修复A3：邻近自助升级写路径不能按回退价格免费放行

重点：src/app/api/workspace/upgrade/route.ts；按需小范围核对workspace-plan-service与workspace-upgrade-service的自助开通边界。

当前targetPlan读不到或抛错会回退常量，cycleAmount<=0就调用provisionEnterpriseUpgrade。这是相同免付款权益边界，不能仅列遗留风险后称无绕行通过。

要求：
- 自助升级写入前严格核验真实目标和免费资格；未知、停用、非法价、读取异常均拒绝。
- 错误/未授权分支不得调用provision、创建订单、改空间类型、迁移/删除资料或发赠送额度。
- 合法免费基础档依原规则处理；未批准零价高级档不能开通。
- 合法正价的既有PENDING下单路径不得被改成直接开通；本批不新增支付类型、不重写履约/席位/资金算法。
- 不能前面严格检查，开通服务随后又以宽松读取/默认值替换已核验目标；必要时传递已核验配置，或在自助来源写边界重新严格确认。
- 只有确实必须重构资金/迁移或需新商业决定时，停止并阻断受影响路径，报告具体原因。不要按模块名字推断整条调用“不在范围”。
