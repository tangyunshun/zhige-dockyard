## 2. I-MONTH-ORDER：修复重置与校验顺序

现状证据：handler 2905/2912 先读旧 monthlyTokenUsed 并拒绝，3398 才做自然月维护。独立对照同样的“月限额1000、旧用量1000、quotaResetAt已到期、本次100点”：R0-H2快照200，当前400且重置函数0次。

采用项目现有逻辑，不修改套餐/额度语义。顺序必须满足：

1. 原身份、空间和必要合同/模型门禁继续有效。
2. 服务端最终模型计划先判定，BYOK 按现有 409 稳定码暂停；它不能先重置配额再拒绝。
3. 对允许的平台任务执行既有 checkAndResetQuotaCycle / 必要配额确保。
4. 重新读取本次有效的成员月度用量，再校验本次任务是否超限。
5. 月额度校验通过后，才允许扣点、hold、创建执行任务和 execute。

选择实现上最小的重排/复用，保留最终计划复核。不要无条件在每次请求把用量清零，不要为了解锁而增大限额或绕过有效月额度，不要拿过期前读取的成员对象继续做已重置后的判断。避免产生错误的“额度不足”通知。

同根因还要覆盖“前期平台、最终BYOK且旧月用尽”的夹具：最终应为暂停，不应提前误报配额不足；配额/资金/任务/执行均不因该请求推进。不得通过移除全部额度检查解决顺序问题。
