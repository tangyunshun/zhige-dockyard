# 四批共同约束与交接协议

所有执行者先完整阅读项目 AGENTS.md、docs/PROJECT-DEVELOPMENT-CHARTER.md、docs/product-business-review-2026-11-05/RESTRUCTURING-PROPOSAL.md 的 F14/F15/F16 与费用不变量，再读本批指令。用户本轮仅授权这些既定安全修复及集成，不是整体产品重构或真实运营写入授权。

## 1. 分开“实现交付”和“独立验收”

A1、B1、A2 可在本地交付后按依赖继续开发；这不代表问题关闭。B2 统一检查也不是独立签收，本助手最后复核。任何原批次必验项都不能自行移出、改名另立项目或删记录。

执行人接单时记录具体任务ID、开始时间、预计交付时间、拟改路径；该时间是执行人估计，不编造固定工期。交付、续期、退回均追加记录，保留原承诺。到点由用户查看对应 IDE/交付目录；本助手在用户回传成果后检查所有未完项，不宣称离线期间自动监督。

## 2. 同目录并行的文件所有权

| 文件/范围 | 唯一写入者 |
| --- | --- |
| F14解析模块、worker、Studio/extract/preview、r0k测试与F14影响的三个旧存储测试 | A1；交付后冻结 |
| F15短信/邮箱验证码及实际注册/登录/找回/绑定调用的最小验证接线、专用测试 | B1；不改核心通用鉴权/计费规则 |
| F16旧直充/线下充值审批入口、最小资金动作守卫、对应页面提示与专用测试 | A2；不改已冻结资金核心算法或F07暂停策略 |
| prisma/schema.prisma | A1正在开发期间仅A1；A1定格后暂不写，直到B2接管集成 |
| F15/F16新模型、迁移需求 | B1/A2各自只交本批独立模型片段和离线SQL草案；由B2统一加入正式schema/migrations |
| security.ts、auth.ts、middleware.ts、credit-service、payment、定价等共享核心 | 默认只读；本轮不重构；必要调用接线优先在本批helper完成 |
| package.json/锁文件、tsconfig、Next共享配置、共用测试配置 | B1/A2不独改；交明确最小变更建议，B2统一处理。A1已获批的worker部署最小配置继续由A1交付 |
| 共享页面如WorkspaceInternalLayoutV3、统一权限配置/目录、全仓检查和最终清单 | B1/A2交最小补丁需求，B2在前三批定格后整合；禁止偷偷给现有用户/角色自动加资金权限 |
| 各自报告/起止副本/结果 | 各自 deliverables/A1、B1、A2、B2，禁止覆盖别人的证据 |

同文件有重叠就停止该文件写入，保留已做工作，交接给指定唯一写入者；其他无依赖工作可以继续。不要因为“可能需要”扩大共享模块改动。未授权的共享核心变更必须列出具体原因和替代方式，不能自行实施。

如果某任务新增一条业务路径使所有权表不覆盖，先把它归到本批直接相关目录并写清；跨批文件不得自行抢占。B1不能修改A1测试来掩盖其失败，A1也不能回滚B1验证码实现。

## 3. 数据模型和迁移只单人集成

B1、A2每个模型片段说明：model名、字段/索引、状态和唯一键、服务端delegate名称、事务/幂等语义、旧数据兼容、缺表/列时的稳定拒绝，以及离线SQL。避免与parselease等现有表混用锁或计数。

片段是待集成，不得宣称已部署。服务先以隔离delegate验证；真实模型缺失时诚实未就绪，不能本机Map降级或业务请求建表。B2接手前，A1对schema的最终SHA必须定格；B2增量合并各片段，不能覆盖整份schema。

不连接真实库、不执行migrate/seed/db push。离线validate/generate若有必要，先核对实际命令的环境读取与写入，不允许借此加载真实.env/连接服务或下载依赖；无法隔离时列环境门，不假装通过。

## 4. 费用和权限底线

- 不读取/复制/打印.env、密钥、客户材料；不调用真实SMTP、短信、模型、支付、云桶；不部署、真实迁移或清理历史数据。
- 不启用真实结算、BYOK收费、支付模拟后门，不改价格/费率/免费权益/会员规则。
- 付款事实、内部账务、权益发放分开；无可信收款/审批/归属证据时拒绝资金写入，不把凭证备注或客户端布尔值当已收款。
- 已冻结F07人工APPROVE暂停保持，合法REJECT与历史查询保持；不能借F16重新开放人工退点。
- 已批准用户流程正常与错误结果都要诚实。没有供应商接通就明确未就绪，不能虚报已发送/已到账；不能用前端按钮隐藏代替后端保护。

## 5. 每批交接的唯一格式

每个 deliverables/<任务>/ 至少包含：

1. report.md：用户流程、原方案编号、已做/未做、具体源码diff、测试与退出码、外部IO隔离、数据/账务影响。
2. manifest.json：基线来源、每个自有修改文件起止SHA、新文件、真实时间；既有文件修改前完整副本和最终副本。缺失旧起点只能如实说明。
3. tests.json及原始结果：精确命令、测试文件/案例、通过/失败/取消，不能只写测试总数。
4. schema/与shared-changes.md（不需要也明确写无）：模型/SQL片段、共享文件补丁建议和原因，供B2集成。
5. handoff.json：任务ID、状态DELIVERED_PENDING_REVIEW、最终SHA清单、仍阻断事项、执行人已停止写入的声明。新修改必须重新交版本，不能悄悄改定格文件。

未完成不是取消；未验证不是通过。初次接单与交付状态写各自目录的 events.md，只追加，主登记由B2收齐时更新；不让两个IDE同时写一个登记文件。

## 6. 测试纪律

优先跑本批精确隔离用例。A1完成原F14必验回归；B1/A2只跑各自范围，遇到另一IDE正在写的全仓类型错误要按路径归因，不修改对方文件。最终B2在全部定格后跑严格类型检查和统一精确基线。

模拟Prisma必须执行条件、唯一性和事务回滚；多实例测试不能两份独立Map各算各的，也不能覆盖计数行或不await竞争屏障。真实route/service接线必须验证，不能只断言helper被调用。

禁止无过滤全仓测试、真实外部IO、实际解压炸弹/OOM；node:test使用匹配runner并加有限超时。测试产物写自己目录，不覆盖现有.next worker/构建结果。模块自检或复制产物测试不冒充真实Next部署/数据库/供应商验收。
