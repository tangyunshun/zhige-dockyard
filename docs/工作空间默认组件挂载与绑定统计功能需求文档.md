# 工作空间默认组件挂载与绑定统计功能需求文档

## 1. 业务背景
在“知阁·舟坊”工坊平台中，工作空间（包含个人开发空间与企业协同空间）是开发效能组件的承载容器。
原系统的组件统计功能存在多处硬编码或不一致的情况：
- 空间中枢显示的组件授权统计为 0 或者是错误的“历史任务数”。
- 默认组件（C01 招标文件智能解析、C02 方案安全合规体检、C07 会议纪要自动转需求(PRD)）的挂载方式在个人空间和企业空间表现不统一，且不支持所有者进行自由的启用和禁用管理。

为了提升组件管理的灵活性和数据的精准性，特进行本次重构。

---

## 2. 核心功能需求

### 2.1 全新空间默认组件载入自愈
- **触发条件**：任何全新创建的工作空间，或者之前没有任何组件操作记录的历史工作空间。
- **业务行为**：系统自动且物理地将 `C01`、`C02`、`C07`（系统预设核心默认组件）绑定至该空间的组件使用关系表（`componentusage`）。
- **生命周期**：默认挂载组件在初始化后处于“已载入/已开启”状态。

### 2.2 灵活的组件管理与解绑
- **操作主体**：工作空间所有者（Owner）或系统管理员。
- **业务行为**：允许所有者在“空间组件管理”页面中，对所有已装配组件（包括系统默认推荐的三个组件）进行自由的解绑（禁用/卸载）和绑定操作。
- **解除装载规则**：解绑后，清除对应的 `componentusage` 记录。该组件在列表中自动切换为“未载入”，且在退出管理页后，空间中枢的绑定统计数同步扣减。

### 2.3 工作空间绑定数量精准统计
- **统计字段**：`componentCount`
- **统计源**：对应空间在 `componentusage` 中去重后的唯一组件数量，代表当前实际挂载可用的组件总数。
- **展示位置**：
  - 空间中枢：个人空间卡片已绑定组件数、企业空间卡片已授权组件数。
  - 列表汇总统计栏：协同空间总组件数量。

---

## 3. 技术实现规范

### 3.1 自愈哨兵函数 `ensureDefaultComponents`
位于 `src/lib/workspaceInit.ts`。
```typescript
export async function ensureDefaultComponents(workspaceId: string, userId?: string)
```
- **核心逻辑**：
  1. 通过 `prisma.workspace` 校验空间。
  2. 统计 `prisma.componentusage.count` 中该空间的记录数。
  3. 若 `count === 0`，说明是初次运行的全新空间，自动将 `["C01", "C02", "C07"]` 的绑定记录以 `crypto.randomUUID()` 写入 `componentusage` 表中。

### 3.2 接口重构一览
- **获取已绑定组件 (`GET /api/studio?action=bound`)**：
  - 调用 `ensureDefaultComponents` 保证自愈状态。
  - 移除原先硬编码在代码中的个人空间合并逻辑。
  - 直接查询 `componentusage` 库并返回。
- **工作空间列表获取 (`GET /api/workspace/list`)**：
  - 异步处理每个空间的自愈函数。
  - 通过 `prisma.componentusage` 统计唯一的已绑定组件总数作为 `componentCount` 返回。
- **企业空间列表获取 (`GET /api/workspace/enterprise-list`)**：
  - 异步处理每个空间的自愈函数。
  - 移除硬编码 `componentCount: 0`，采用 `componentusage` 唯一组件数作为统计数值返回。
- **创建企业工作空间 (`POST /api/workspace/create-enterprise`)**：
  - 在创建完毕空间、配额和成员后，直接物理写入默认的 3 个组件到 `componentusage`。

### 3.3 工作台组件启用与禁用管理交互
- **组件卡片展示范围**：工作空间内的组件列表仅展示已装配（已载入）的组件。未去组件大厅装配的组件不在列表里呈现。
- **已装配组件的启用/禁用状态控制**：
  - **启用与禁用控制**：工作空间所有者（Owner）或管理员（Admin）可在工作台组件卡片中，对已载入的组件进行一键“启用”或“禁用”的操作。
  - **二次确认**：点击“禁用”时，前端必须启动确认提醒（弹出二次确认弹窗），确保是预期的禁用行为。
  - **强行锁死**：组件被禁用后（状态标记为 `○ 已禁用`），该组件卡片右下角的“开始使用”按钮将被置灰且不可点击，从而锁死对此组件的访问与操作。
  - **RBAC 角色隔离**：普通工作空间成员无法看到启用/禁用按钮（只读显示“管理员已禁用”），无权控制状态。
- **与组件卸载（Unbind）的区别与联动控制**：
  - 卸载会将组件彻底从该工作空间列表中移去。点击“卸载”需要触发数据依赖自愈诊断与确认。
  - 禁用仅使组件暂时停用（保留装配记录，置灰使用按钮），方便随时一键重新开启。
  - **强制启用中禁止卸载联动约束**：
    - 在企业空间中，任何组件如果处于启用（已开启）状态下，则卸载按钮将被前台强行置灰并禁用，同时在卸载逻辑层直接阻断拦截，强迫用户必须先执行“禁用”操作后才能卸载，防止误删线上在运业务组件。个人空间不做限制。
  - **组件大厅死循环性能防御**：
    - 子组件监听绑定数据变化时，严禁直接将数组型 `boundComponentIds` 放入 `useEffect` 依赖数组，必须升级使用值类型拼接字符串 `boundComponentIds.join(",")` 依赖，以百分之百杜绝引用类型重绘引发的无限 API 请求与渲染死循环，消除潜在 Issue 报错隐患。
  - **安全受限组件的黄色徽标与引导提示设计**：
    - 在企业协同空间中，对于被安全矩阵限制的组件（由于岗位未授权等原因受限），除将右下角“开始使用”按钮置灰外，必须在卡片右上角显著呈现亮黄色的 `⚠️ 岗位限制` 徽标，并在卡片中央描述下方注入黄色指引提示：`🔒 提示：当前开发岗位未分配此组件的执行权限，请联系管理员分配该岗位。`
    - 让颜色具有明确的业务语义（蓝色＝正常使用，黄色＝岗位限制，绿色＝启用，灰色＝禁用/卸载阻断），规避使用者的视觉混淆，打通权限闭环。
  - **工作控制台成员面板邀请链接多端同步规范**：
    - 在企业协作工作空间控制台的“成员”面板中，必须同步拉取并展示与空间中枢完全对齐的“待加入的邀请记录历史列表”。
    - 列表包含当前空间下尚未过期且仍为 PENDING 状态的邀请记录，并为管理者配备复制邀请函链接与一键 POST `/api/workspace/invitation/delete` 作废邀请码的能力，达成多入口管理、状态实时同步的数据闭环。
  - **等待激活受邀人列表混排展示与撤回设计规范**：
    - 在控制台的“协作者列表”底部，必须将尚未登录激活的 Pending 邀请人记录作为待激活行进行混排渲染。
    - 待激活行需通过黄色边框（`border-l-4 border-amber-450`）和 `Pending` 徽标突显，并提供给管理者垃圾桶撤回按钮，点击可一键物理作废并删除该邀请码，实现未激活成员的直接移除闭环。
