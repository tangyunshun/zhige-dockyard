# 模块覆盖与后续验收矩阵

这是设计审核范围与后续验证要求，不是“所有功能已通过测试”的记录。静态取证只证明相应实现/问题存在；数据库、渠道、渲染、用户效果和经营结果分别需要证据。费用入口符号清单见[机器证据](source-evidence.json)，风险和阶段编号见[主方案](RESTRUCTURING-PROPOSAL.md)。

| 模块/目标用户 | 本轮观察与证据 | 需求重构落点 | 后续验收 |
|---|---|---|---|
| 首页/访客 | Hero/CTA源码；固定效果数字、模拟切换、抽象标题 | 表达用户、任务、成果与范围；明确示例和真实提交 | 浏览器与陌生目标用户测试；不引用虚构能力/客户证言 |
| 场景/解决方案/访客 | 入口与组件目录/合同的关系静态追踪，未逐项验收所有场景 | 仅展示可提供的能力，咨询与在线执行分开 | 每个公开收费场景有授权样本与人工签收 |
| 注册/新用户 | register、login/create-personal、验证码源码 | 账户和个人空间一次准备；不丢原任务意图 | 重复注册/并发创建、身份验证、失败恢复与正常入门 |
| 登录/安全/全部用户 | 完整validateUser与弱平台兜底；前报告 | 服务端状态统一；Cookie/Bearer仅凭证提取不同 | 封禁/注销/撤销/过期/踢线，各入口与Key分别验证 |
| 个人资料/设备/账号删除 | 目录与既有状态字段盘点，未逐接口动态测试 | 个人数据生命周期与企业资产分开 | 注销不销毁企业成果，恢复范围与敏感变更验证 |
| 空间中枢/新老用户 | workspace-hub、studio、快捷工具源码 | 首次获得结果与继续任务优先；空间不成为不必要门槛 | 新/老/企业成员三套入口、空态与失败状态 |
| 企业创建/购买人 | create-enterprise接收plan；升级两条链路策略不同 | 可购买不等于已购买；组织归属与付款凭证绑定 | 免费与付费创建、空间数量并发限制、已付恢复 |
| 成员/岗位/企业管理 | security逻辑角色、成员预算及余额结构 | 预算/划拨区分，当前权限不依赖可删审计日志 | 邀请、审批、离职、负责人交接、Key撤销 |
| 组件/产品运营 | catalog/contract、公开营销承诺、studio门禁 | 目录、合同、可执行、业务验收分状态；不按组件编号写规则 | 未激活/未支持输出/部署不可用时诚实阻断 |
| 执行/普通用户 | Studio/Open共享核心、固定扣点、成本只警告 | 报价与成本预留、任务/attempt、预算和恢复 | 重复提交、超预算、重启、超时未知、并发扣款 |
| 结果/用户 | 已有结果展示与合同校验结构，未浏览器逐输出验证 | 结构通过与业务认可分开，来源与需复核处可见 | 各输出可用、失败不假成功、导出内容一致 |
| 资料/知识/团队 | document等实体、存储/解析服务、既有治理入口 | 来源/版本/权限/失效与引用关联 | 跨空间读取、撤回引用、分享失效、离职与删除 |
| 文件解析/上传/下载 | extract-text有局部并发与超时；storage quota缺失放行 | 预留资源、真正取消、物理文件/DB恢复与成本归属 | 压缩炸弹、大文件、多实例、并发超额、文件读写权限 |
| 会员/个人购买人 | membership/upgrade无支付直接生效；隔离复现额度快照翻倍 | 用户级个人价值与企业级权益分开；统一履约 | 不付款不生效、并发购买、期满/续费、跨空间发放守恒 |
| 企业套餐/购买人 | upgrade-plan直接开通；另有正确PENDING入口 | 只认订单/授权；升级/续费/到期统一规则 | 所有入口直接调用、套餐并发、降级超额不误删 |
| 席位/企业购买人 | fulfill并发隔离复现重复增发 | 业务唯一发放凭证、事务一致性、按期权益 | 同单并发/失败恢复；老套餐到期后不误挂新套餐 |
| 充值/财务 | createCharge/回调存在；mock生产显式可用；legacy直充读权限 | 环境隔离、收款凭据、金额单位、逐类型权益履约 | 验签与商户/金额/币种/交易号；真实/模拟/补录分开 |
| 钱包/池/成员资金 | grantPoints、recycle；来源桶不减的隔离复现 | 真源明确、账户与分桶守恒、资金属性不丢失 | 并发划拨/回收、过期/退款与锁顺序、余额和桶核对 |
| 退款/用户与财务 | 人工统一退钱包；申请汇总原扣，未统一净可退额 | 同一任务可退总额与原付款方统一控制 | 自动+人工双退、批准/拒绝/撤销并发、赠送变现阻断 |
| 赠送/运营 | register gift、新空间gift、plan trialGift等不同来源 | 活动资格、叠加规则、预算、期限和转账限制统一 | 多账号/重建/并发领取；已有承诺不无故收回 |
| 模型/BYO/管理员 | registry、test接口、BYOK115%公式 | 真实能力、数据接收范围、服务费、密钥与测试预算 | 不可用/成本缺失、切换授权、密钥不被带往新目标 |
| 开放API/开发者 | Key鉴权状态缺口；execute复用核心；sandbox返回501 | Key范围/预算/撤销与账号业务状态；不可用文档明确 | 错Key、撤销、禁用、跨空间、轮询、费用一致 |
| 短信邮件/访客 | SMS TODO却成功；SMTP发送与进程限流 | 发送真实状态、验证码不记明文日志、共享限流和总预算 | 发送失败、重发、验证码生命周期、多实例与滥用 |
| 管理运营/各职责 | order:read用于退款/直充；高危日志可能非阻断 | 读写权限分离，收款核实、审批、强审计、恢复中心 | 读角色不能写钱；自批/批量操作边界；审计失败 |
| 经营统计/负责人 | analytics基于登录和任务计数；余额汇总以快照为主 | 有效成果、cohort、付费/赠送分开与成本归因 | 与任务/渠道账单核对；测试不算收入，转账不算新增收入 |
| 维护/调度/平台 | 公开GET可关闭维护；到期cron缺secret时放行 | 查询无写入、缺凭证拒绝、费用暂停与站点维护分开 | 匿名/错误密钥/重复调度、平台限额不中断必要查询 |
| 备份/发布/值守 | 本轮没有恢复演练、生产监控或账单证据 | 数据迁移/回滚、值守、预算告警和供应商核对 | 数据与文件一起恢复；已付款事实不因回滚消失 |

必须在真实环境补足的输入：实际部署版本与迁移、支付模式与隔离方式（仅核对状态，不打印密钥）、真实供应商成本/账单、支付费率和固定开支、当前有效套餐/赠送/折扣、订单及余额只读差异清单、目标用户样本和历史使用周期。没有这些数据，不能给出可信的净利润、推广预算、转化率目标或“已无费用漏洞”的结论。
