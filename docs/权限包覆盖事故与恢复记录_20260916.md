# 权限包覆盖事故与恢复记录（2026-09-16）

> 记录一次**由自动化脚本引发的管理员权限包被覆盖**事故的完整过程、根因、恢复方式与防复发措施。

---

## 一、事故现象

在执行「委派授权 + 目录清理」脚本（`scripts/delegate-and-cleanup-permissions.ts`）后，平台管理员 `admin`
的权限包被**覆盖为仅剩 2 个键**（`permission:manage`、`system:manage`），原先约 66 项权限全部丢失。

接口侧表现（用该管理员凭证实测）：

| 接口 | 事故后 | 期望 |
|---|---|---|
| `GET /api/admin/notifications` | 403 `{"error":"FORBIDDEN","required":["announcement:read"]}` | 200 |
| `GET /api/admin/recharge-orders` | 403 `{"error":"FORBIDDEN","message":"缺少接口权限：order:detail"}` | 200 |
| `GET /api/admin/settings` | 200（因刚授予 `system:manage`） | 200 |

## 二、根因

脚本中**自行拼接了权限包的存储 key**，且拼错：

```ts
// ❌ 错误写法（脚本内）
const PERMISSIONS_KEY = "PLATFORM_ADMIN_PERMISSIONS_V1";
```

而 `src/lib/security.ts` 中的真实常量为：

```ts
const ADMIN_PERMISSIONS_CONFIG_KEY = "platform_admin_permissions"; // ✅ 真实 key
```

→ 读取到 `undefined` → 解析为空映射 `{}` → 授权时以"空包 + 2 个新键"整体写回
→ `saveAdminPermissions()` 是**整包覆盖**语义，导致原有权限被清空。

## 三、影响范围

- 仅影响 `systemconfig.platform_admin_permissions` 中的**该管理员权限包**；
- 未影响权限目录、接口权限规则、业务数据；
- 因影响面是"管理员后台权限"，前台用户与业务数据无影响。

## 四、恢复过程（已全部完成并验证）

1. 定位真实 key：`platform_admin_permissions`；
2. **多源取并集恢复**（只增不减，绝不进一步扩大损失）：
   - `D:\db-backup\*.sql`（6 份备份，各含原始 54 项权限）
   - `src/lib/admin-permissions.json`（JSON 回退文件，15 项）
   - 数据库当前值（2 项）
   → `2 → 57` 项；
3. 重跑 `npm run wire:admin-permission-rules`（幂等、先授权后启用）→ 再补 **20** 项接线键；
4. 重启服务清缓存后实测：`notifications` **200**、`recharge-orders` **200**、`settings` **200**、
   `clean-test-appeal` **403**（超管专属，符合预期）。

恢复工具脚本为一次性脚本，执行后已删除；备份文件保留在 `scripts/data/backup-permissions-*.json`。

## 五、防复发措施（已落地）

1. **脚本禁止自行拼 key**：`delegate-and-cleanup-permissions.ts` 已改为强制走
   `getAdminPermissions()` / `saveAdminPermissions()`，并在注释中写明"严禁自行拼 key"；
2. **操作前自动备份**：该脚本执行前会把「权限目录 + 管理员权限包 + 接口权限规则」备份到
   `scripts/data/backup-permissions-<时间戳>.json`，并在输出中提示回滚方式；
3. **取并集而非覆盖**：恢复与授权逻辑一律使用 `Array.from(new Set([...]))` 合并，避免缩小权限集合；
4. **幂等 + 预演**：所有权限类脚本支持 `--dry-run`，重复执行无副作用；
5. **删除前校验**：清理权限点前会校验该键确实不在代码/规则中被引用
   （本次仍误删了被后台菜单引用的 `content:read`，已从备份恢复，并已把该键加入"禁止移除"说明）。

## 六、教训

- **不要把"常量名"当作稳定契约**：跨文件引用存储 key 时，必须 import 常量或调用封装函数；
- **写操作脚本要有"最小影响"设计**：默认并集、可预演、有备份、可回滚；
- **覆盖型 API 要显式告警**：`saveAdminPermissions()` 是整包覆盖，调用前应先读取并要求调用方确认。
